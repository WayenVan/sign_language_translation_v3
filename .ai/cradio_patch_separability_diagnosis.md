# C-RADIOv4 Patch 特征可分性诊断

日期：2026-08-31

## 结论先行

为了给「视觉 token 筛选」方案选打分器和特征层，对 `C-RADIOv4-SO400M` 的全部 27 个
block 做了逐层线性探针诊断。三条结论：

1. **末层特征没有被背景污染，`output_layer: [-1]` 不用改。** block -1 的探针
   AUC = 0.998，与任何中间层完全相同；overlay 图里 block -1 依然干净地圈出手和脸。
   「深层 self-attention 扫到背景导致特征质量下降」这个担心**实测不成立**。
2. **CLS attention 单独用是个人脸选择器，会系统性地丢手。** 在「手 vs 脸」任务上它的
   AUC 低到 **0.034**（几乎完美的*反向*分类器）。落到实际用途上：在 `-8` 层做
   平滑 + 去角 + top-48，**脸的召回 0.99，手的召回只有 0.25**——四分之三的手 patch 被扔掉。
   补救是配一个**帧间运动**打分器（手的召回在 k=32 时 0.81，而脸只有 0.15），
   两者互补。详见第 5.1 节。`feature-norm deviation` 同样偏向脸。
3. **两个探针任务都饱和了（全部 27 层 AUC ≥ 0.99），说明 patch 特征不是瓶颈。**
   token 筛选因此无法「提供新信息」，只能「改变池化的信噪比」，收益上限被压低。
   下一个该测的是**手型细节**，而不是继续调筛选模块。

## 1. 实验设置

| 项 | 值 |
| --- | --- |
| Backbone | `nvidia/C-RADIOv4-SO400M`，27 个 block，width 1152 |
| 输入 | 224×224 → 14×14 = 196 patch，`do_normalize=false` |
| 样本 | val split 40 个视频 × 6 个**连续帧对** (t-1, t) = 240 帧 |
| 标签 | MediaPipe Tasks（hand + face landmarker，512px 上检测），**240/240 帧全部检出** |
| 探针 | `LogisticRegression(C=0.01)`，训练侧负样本降采样到 3:1，测试侧保持自然分布 |
| 切分 | **按 video 分组**（28 训练 / 12 测试视频） |

三个必须堵的坑，脚本里都处理了：

- **按 video 切分**，不能按 patch 或帧切——同帧相邻 patch 高度相关，按 patch 切会让每层
  AUC 都顶到 0.99，曲线整体平掉。
- **位置基线**：只用 `(row, col, row², col²)` 拟合的探针。手语视频里手的位置分布极集中，
  这条地板线本身就有 0.906 / 0.964，特征只有超出它的部分才算真本事。
- **忽略环**：正 patch 的 8 邻域标 `-1` 排除。半只手的 patch 归哪类都是错的。

代码：`experiments/diagnose/{extract,probe,relabel}.py`。
特征缓存 `outputs/diagnose/features.npz`（2.6 GB，含 features / cls_attention / motion /
frames / labels），**复跑探针不需要重跑 backbone**。

## 2. 任务 A：手/脸 vs 背景

位置基线 AUC = **0.906**。

| block | 探针 AUC | 平均两两余弦 | Fisher ratio |
| ---: | ---: | ---: | ---: |
| -27（第一层） | 0.995 | 0.557 | 0.419 |
| -16（最佳） | 0.998 | 0.307 | 0.534 |
| -13 | 0.998 | 0.292 | 0.502 |
| -4 | 0.998 | 0.476 | 0.454 |
| **-1** | **0.998** | **0.668** | **0.223** |

AUC 在全部 27 层都是 0.995–0.998。**连第一个 block 都有 0.995**——这说明探针大概率在学
**肤色**：PHOENIX14T 里手和脸是画面上唯一的皮肤，深色衣服 + 灰色背景。任务太简单。

## 3. 任务 B：手 vs 脸（去掉肤色捷径）

只保留皮肤 patch，手=正、脸=负，手脸重叠的 patch 排除。位置基线 AUC = **0.964**
（脸恒在上方中央，手在下方，位置几乎能直接分开）。

AUC 依然是全部层 0.994–1.000。**两个任务都饱和。**

## 4. Over-smoothing：存在，但塌掉的不是需要的那个维度

余弦相似度从中层的 ~0.27–0.31 升到 block -1 的 **0.668**，塌缩信号是真的。但 Fisher ratio
的两个任务方向**相反**：

| Fisher ratio | 中间层 | block -1 |
| --- | ---: | ---: |
| 手/脸 **vs 背景** | ~0.55 | **0.223** ↓ |
| **手 vs 脸** | ~0.50 | **0.721** ↑ |

末层**弱化图/底区分、强化部位语义区分**。这与 RADIO 的蒸馏目标一致：末层对齐的是
DINOv3-dense 和 SAM3，那是部位/物体语义的老师。末层在答「这是手还是脸」，
不在答「这是人还是背景」。

这也解释了为什么 AUC 不掉而 Fisher 掉：线性可分性对 margin 收缩不敏感。
**只看 AUC 会漏掉这个现象，必须同时看 Fisher 和余弦。**

## 5. 打分器对比（本次诊断最重要的结果）

四个候选用同一套留出标签、同一个 AUC 直接比较：

| 打分器 | 任务 A（手/脸 vs 背景） | 任务 B（手 vs 脸） |
| --- | --- | --- |
| **训练的线性探针** | **0.998** | **1.000** |
| 帧间运动 ‖f_t − f_{t−1}‖ | 0.736 均值（峰 0.875 @ -27） | **0.899 均值，逐层平稳**（峰 0.923 @ -21） |
| CLS attention | 0.835 均值，**0.639–0.953 剧烈震荡** | **0.285 均值，最低 0.034 @ -9（反向）** |
| feature-norm deviation | 0.926 均值（峰 0.960 @ -23） | **0.331 均值（反向）** |
| *位置基线* | *0.906* | *0.964* |

三个要点：

- **CLS attention 只编码「是不是这个人」，完全不编码「是不是手」。** 任务 B 上 AUC 0.034
  意味着它稳定地反着排。而且即使在它擅长的任务 A 上也**极不稳定**，层间在 0.639–0.953
  锯齿状震荡（-15 / -18 掉到 0.64）。肉眼在 -12~-14 看到的手部热点是真的，但相对强度上
  脸压倒性更高。
- **帧间运动是唯一可用的无监督信号**，而且只在真正重要的区分上有用：手和脸都是「人」，
  运动分不出图/底；但**只有手在动**，所以它精确地分出了手。它在最早的层最强
  （-27~-21），说明**像素级帧差就够，不需要深层特征**。
- **训练的线性探针在两个任务上都接近完美**，所以「把 MediaPipe 监督蒸馏进一个冻结的
  `Linear(1152→1)`」这条路技术可行：训练时零可训练参数，推理时不需要跑姿态估计。

## 5.1 recall@k：AUC 之外，真正该看的统计量

AUC 问的是「手有没有排在脸前面」，但选择器不需要那个顺序正确，只需要手落进保留集里。
两者是不同的问题，**recall@k 才匹配打分器的实际用法**。

用 `experiments/visualize_cradio_attention.py` 里那套后处理（3×3 边缘校正均值 + 前后各去一次
四角）重测，219 帧同时含手和脸，平均每帧 **11.5 个手 patch / 14.3 个脸 patch**：

| 打分器 | k=16 | k=24 | k=32 | k=48 |
| --- | ---: | ---: | ---: | ---: |
| CLS **-8**（脚本默认层）手召回 | 0.02 | 0.06 | 0.12 | **0.25** |
| CLS -8 脸召回 | 0.81 | 0.93 | 0.97 | 0.99 |
| CLS -13 手召回 | 0.04 | 0.18 | 0.38 | 0.71 |
| CLS -16 手召回 | 0.08 | 0.15 | 0.24 | 0.43 |
| CLS -25 手召回 | 0.26 | 0.43 | 0.60 | 0.83 |
| **帧间运动 -21 手召回** | **0.59** | **0.72** | **0.81** | **0.91** |
| 帧间运动 -21 脸召回 | — | — | 0.15 | — |

三个要点：

- **脚本默认的 `ATTENTION_LAYER = -8` 是所有候选层里对手最差的。** top-48 只留下 1/4 的手
  patch。肉眼看 overlay 觉得「手拿到了」是因为亮起的 patch 确实落在手上，
  但**只是手的一小部分**，而脸几乎全亮。层选择对手的召回影响巨大（-8 的 0.25 vs -25 的 0.83）。
- **运动和 CLS attention 严格互补**：运动抓手不抓脸，CLS 抓脸不抓手。
- 组合（按帧做秩归一化后加权）在 k=32 时：

  | 组合 | 手召回 | 脸召回 |
  | --- | ---: | ---: |
  | 50% 运动 + 50% CLS-13 | **0.84** | 0.54 |
  | 70% 运动 + 30% CLS-13 | 0.87 | 0.33 |
  | 各取 top-16 求并集（实际保留 30.7 个） | 0.61 | **0.86** |

  加权组合偏手，预算并集偏脸。**手承载词汇内容、脸承载语法/韵律标记**，
  所以更可能要的是一个偏手的非对称预算划分。

## 6. 对设计的结论

1. **特征层：`output_layer: [-1]` 保持不变。** 已证伪，不需要融合中层。
2. **打分器：CLS attention 不能单独用。** 三个可行方向：(a) **帧间运动 + CLS attention
   组合**（两者零参数、严格互补，见 5.1 节）；(b) 用 MediaPipe 标签离线拟合并**冻结**的
   `Linear(1152→1)`（AUC 1.000，训练时零可训练参数，推理时不需要跑姿态估计）；
   (c) 两者再组合。**如果坚持用 CLS attention，`attention_layer` 要从 -8 改到 -25 附近**——
   这一个改动就把 top-48 的手召回从 0.25 提到 0.83。
3. **在动筛选之前，先测手型。** 224×224 下一只手只有 2–4 个 patch。「这是手」很好分，
   但「这是**哪个**手型」可能压根没编码——这才是可疑的真瓶颈。用 MediaPipe 的 21 个手指
   关节坐标当标签、从 patch 特征回归即可，**现有 features.npz 就能跑**。
   如果手型探针也差，那分辨率（224 → 384/512，C-RADIOv4 的 `preferred_resolution` 是 512）
   是比任何筛选模块都大的杠杆，应该先动它。

## 7. 本次诊断没有回答的问题

- **手型可分性**（见上，最重要的缺口）。
- 像素空间的帧差——本次的 motion 是**特征空间**的 `‖f_t − f_{t−1}‖`，对「手在动」这个
  假设不是最公平的检验（而它已经是最强的无监督手部信号了，像素级可能更好）。
- artifact 的位置不变性检验（换 signer 后边缘尖峰是否还在同一位置）。
- 分数平滑（3×3 空间 + ±1 时间）对 top-k 覆盖率的影响。
