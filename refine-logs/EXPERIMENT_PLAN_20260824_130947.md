# 实验计划：单语性能受限时如何建立可信的统一多语言 SLT 论证

**问题**：当前模型的单语言翻译性能弱于部分专用 SLT 系统，但目标是研究一个 checkpoint 下由自然语言指令控制目标语言的多语言 SLT。

**方法论点**：不回避绝对性能差距，而是量化统一模型相对于同架构单语上界的性能保留、相对于 language-ID 控制的新增能力，以及性能—覆盖—成本的 Pareto 权衡。

**日期**：2026-08-24

## Claim Map

| Claim | 为什么重要 | 最低可信证据 | 对应实验 |
|---|---|---|---|
| C1：统一模型在一个 checkpoint 中覆盖多个目标语言，并保留可接受的单语能力 | 回答“功能更多但是否仍可用” | 与同架构、同数据、同预算单语 specialist 比较；逐语言报告 retention | B1 |
| C2：统一训练带来的价值不能由简单 language ID 完全替代 | 防止 instruction 被认为只是更长的语言标签 | 相同架构/数据/预算下比较 language ID、固定 prompt、多样 prompt；指令泛化由后续计划单独展开 | B2 |
| Anti-claim：低 BLEU 只是被额外能力掩盖 | 必须承认并界定性能代价 | 外部强模型作为 reference；报告绝对差距、参数、训练数和 checkpoint 数；预设最低可用门槛 | B1、B3 |

## Paper Storyline

- 主文必须证明：单模型覆盖多语言；相对自身单语上界的性能损失有限；对比专用系统时在模型数量、语言覆盖和控制接口上形成明确 trade-off。
- Appendix 支撑：外部前端迁移的负结果、逐样本误差、长度/语言分桶、额外指标。
- 明确不声称：单语 SOTA、零样本目标语言翻译、所有性能差距都来自他人 decoder。

## Experiment Blocks

### B0：评测协议冻结与可用性校验

- **Claim tested**：后续差距不是 metric、decode 或数据不一致造成的。
- **系统**：当前最佳单语 checkpoint 与统一模型的最小可运行版本。
- **设置**：固定 split、tokenization、beam size、最大生成长度和文本规范化；保存逐样本输出。
- **指标**：BLEU-4、ROUGE-L、COMET/XCOMET（若覆盖对应语言）、输出语言正确率、长度比。
- **成功标准**：重复评测数值完全一致；200–500 个训练样本可过拟合；reference 文本语言检测接近 100%。
- **失败解释**：在此阶段停止主实验，先修正评测。
- **优先级**：MUST-RUN。

### B1：自身单语上界与 Unified Retention（主结果）

- **Claim tested**：统一模型付出的性能代价是否可接受。
- **比较系统**：
  1. `Mono-DE / Mono-EN / Mono-ZH`：完全相同架构，各自只训练一个目标语言；
  2. `Unified-LID`：一个 checkpoint，用 language ID 控制；
  3. `Unified-Instruct`：一个 checkpoint，用自然语言指令控制；
  4. 外部强专用模型：只作 literature/reference row，若协议无法严格匹配则明确标注不可直接比较。
- **公平约束**：相同视觉输入、训练样本预算定义、decode 和 metric。另报告“每种语言总训练曝光量”，避免 unified 因看了更多样本而不公平。
- **主要指标**：逐语言 BLEU-4、ROUGE-L、COMET/XCOMET。
- **派生指标**：
  - `Retention_l = Unified_l / Mono_l × 100%`；
  - Macro average（各语言等权）；
  - 最差语言表现；
  - `Checkpoints required`、总参数存储和训练总成本。
- **建议成功门槛**：平均 retention ≥ 85%，且没有任一语言低于 75%；若语义指标 retention 明显高于 BLEU，也可支撑“语义保留、表面表达较弱”的有限结论。
- **失败解释**：
  - 75–85%：论文必须以 trade-off/能力研究定位，并加强错误分析；
  - <75%：不能仅靠 instruction 能力补偿，应先处理 multilingual interference 或缩小语言集合；
  - Unified 高于 Mono：检查数据曝光量和正则化效应，不直接宣称 instruction 增益。
- **Table target**：主文 Table 1。
- **优先级**：MUST-RUN。

### B2：性能损失来自哪里（控制机制隔离）

- **Claim tested**：单语差距来自统一多语言训练、instruction 表达，还是视觉/decoder 基础能力。
- **比较系统**：
  1. Mono specialist；
  2. Unified-LID；
  3. Unified-FixedPrompt（每个目标语言一个固定句式）；
  4. Unified-DiversePrompt；
  5. 可选：Unified-DiversePrompt + language-balanced sampling。
- **固定项**：架构、初始化、每语言数据、优化器、训练步数和 decode。
- **判读**：
  - `Mono → Unified-LID`：multilingual interference；
  - `Unified-LID → FixedPrompt`：自然语言接口成本；
  - `FixedPrompt → DiversePrompt`：prompt diversity 的训练成本或正则化收益。
- **成功标准**：instruction 接口相对 Unified-LID 的平均损失 ≤ 1 BLEU 或 ≤3% 相对语义指标；否则需要调 sampling/loss balance，而不是继续扩大 prompt bank。
- **Table target**：主文 Table 2。
- **优先级**：MUST-RUN。

### B3：能力—性能—成本 Pareto

- **Claim tested**：即使绝对 BLEU 不是最高，统一模型是否提供可量化的系统价值。
- **比较维度**：平均翻译质量、支持目标语言数、checkpoint 数、总存储、训练总 GPU 成本、是否支持自然语言控制、是否需要离线 MLLM 描述/语言专用 decoder。
- **公平表达**：外部方法缺失的量标 `N/R`，不自行推断；literature scores 与 reproduced scores 分栏。
- **成功标准**：Unified-Instruct 在相近质量区间显著减少 checkpoint/存储，或在相同 checkpoint 数下提供更多语言和控制能力。
- **失败解释**：如果质量明显掉出可用区且成本更高，Pareto 论证不成立。
- **Figure target**：质量—语言覆盖散点图；点大小表示 checkpoint/存储成本。
- **优先级**：MUST-RUN。

### B4：低单语性能的诚实诊断

- **Claim tested**：确认性能差距的具体来源，并限定结论。
- **分析**：按目标语言、参考长度、视频长度和句法复杂度分桶；报告 hallucination、遗漏、目标语言错误、专名/数字/天气实体错误。
- **视觉依赖控制**：正常视频、zero video、跨样本 wrong video、frame shuffle。
- **成功标准**：正常视频相对 wrong/zero video 有显著指标下降，证明模型不是只靠 Qwen 语言先验；找出最主要的性能损失类型。
- **Table target**：主文一张小表 + qualitative figure；完整分桶放 appendix。
- **优先级**：MUST-RUN（无需重新训练）。

## Run Order and Milestones

| Milestone | Goal | Runs | Decision Gate | 估算成本 | 风险 |
|---|---|---:|---|---|---|
| M0 | 冻结评测 | 0–1 个短 sanity | 可复现且能过拟合小集 | <0.1 full run | metric/生成配置错误 |
| M1 | 获取自身上界 | 每语言 1 seed mono | 得到可信 Mono 上界 | 3 full runs | 单语本身过低 |
| M2 | 分离控制成本 | LID、Fixed、Diverse 各 1 seed | instruction 相对 LID 损失可控 | 3 full runs | multilingual interference |
| M3 | 决策补 seeds | 只给 Mono/LID/最终模型补至 3 seeds | 主要结论跨 seed 稳定 | 最多 6 additional runs | 预算膨胀 |
| M4 | 无训练诊断 | 扰动评测与误差分桶 | 证明视觉依赖并限定失败 | evaluation only | 语言检测偏差 |

## Stop / Go 决策

1. **先跑 Unified-LID**。若它已显著落后 Mono，问题是 multilingual interference，不是 prompt；先做 language-balanced sampling、每语言 loss normalization 或 adapter/LoRA specialization。
2. 若 Unified-LID 接近 Mono，但 instruction 版本明显下降，缩小 prompt diversity，先用固定 prompt warm-up，再逐步加入 paraphrase。
3. 若所有自有模型单语都远低于可用线，不再宣称高质量翻译系统；将论文降格为 controlled study 风险很高，优先加入强视觉预训练/checkpoint 或限制到表现最稳的语言集合。
4. 只有达到预设 retention/可用门槛后，才进入“见过/未见 prompt”的第 1 点实验。

## 如何弥补而不是掩盖单语较弱

- **主要比较对象改为同架构 Mono specialist**：这是统一化代价的唯一干净上界。
- **同时保留外部绝对分数**：诚实展示领域位置，避免选择性汇报。
- **增加语义指标和人工错误分类**：若 BLEU 对多种合法表述惩罚过重，语义指标可以提供补充，但不能替代 BLEU。
- **报告系统效率**：一个 checkpoint 与 N 个 specialist 的存储、部署和训练成本。
- **使用 Pareto claim**：只在质量仍处于可用区时成立；不能把严重性能下降包装成能力优势。
- **必要时缩小语言集合**：两种语言上结论扎实优于三种语言全部不稳定。
